# PairLink Android 0.2.0 / Railway

供双方主动安装、授权和开启共享的 Android 手机指令项目。一个仓库包含 `android/` 客户端和 `railway/` Railway 服务端。

Android 0.2.0 将界面迁移为 Compose + Miuix 0.9.3：默认蓝色主题、夜间模式（系统 / 开启 / 关闭）、按钮、输入框、开关、卡片、进度条及弹窗。已设置白底小猫应用图标，结果页面提供箭头返回；前台服务保留系统要求的通知小图标。服务端仅使用 Railway。Dhizuku 和夜间模式改动仅在客户端，不需要修改服务端接口。

## 第一版

- 两台手机安装同一 APK，双方设备 ID 互相填写。
- 查看对方是否可连接、设备型号、安卓版本、开机时长、当前屏幕应用、电量和充电状态。
- 查看对方已安装的用户应用。
- 查看最近 24 小时使用过的应用，每个应用显示最近一次打开时间，最多 50 条。
- 查看对方系统媒体面板的播放应用、曲目名称、作者、专辑、播放状态和进度；媒体共享默认关闭，需要通知访问权限，无需 root。
- 查看对方通知中心当前的通知：应用名、包名、标题、正文和通知时间。通知共享默认关闭，需要接收方单独开启并授予系统通知访问权限。
- 向对方发送普通系统通知；接收方单独开启发送授权。
- 单次远程 Shell：普通应用、root 或 Shizuku/Sui 执行；标准输出、错误输出、退出码、超时和截断标记。
- 暂停和恢复指定包名的应用：被操作手机选择 Dhizuku、Shizuku/Sui 或 root，独立授权开关默认关闭；提供本机恢复入口。
- 本机应用暂停黑名单：通过本机用户应用选择器搜索、多选并保存，黑名单中的应用不能被对方通过应用暂停功能暂停；仍允许恢复。
- 本机主动开启 Shell；root 必须单独请求本机 root 管理器授权。关闭 Shell 同时关闭 root。
- 夜间模式菜单：系统、开启、关闭；默认跟随系统，选择会保存在本机并立即应用。
- 前台通知、暂停共享、WebSocket 心跳与断线重连；使用系统 DNS。
- 请求结果保留 24 小时后自动清理。第一版没有 MCP、OAuth、API Key 或账号。

## 部署 Railway

部署步骤见 [railway/README.md](railway/README.md)。在 Railway 从本仓库创建服务，Root Directory 设置为 `/railway`，使用 Dockerfile 自动构建；添加挂载至 `/data` 的 Volume，并设置 `DATA_DIR=/data`，健康检查路径 `/health`。保持单实例并关闭自动休眠，然后生成服务域名。双方手机暂停共享，填写同一个 Railway HTTPS 根地址并保存，重新开启共享即可，不需要重新编译 APK。

## 概览与版本号

概览将设备型号、安卓版本、客户端版本号、服务端版本号和双方设备 ID 连续显示在同一卡片中，不再分为“本机信息”和“设备 ID”分类。服务端版本号位于客户端版本号下方，点击即可从已保存服务器的 `/health` 读取 `version`，刷新期间显示“正在刷新”。设置页每次测试服务器连接，也同步更新该版本号。

最近成功获取的版本号按服务器地址保存在本机；更换地址后不会显示原服务器的版本。刷新失败会提示原因并保留最近获取的值；服务端未返回有效版本字符串时显示“未提供版本号”。尚未查询时显示“未获取，点击刷新”，不在启动时自动请求服务器。

## 编译 APK

要求 Android 8.0 或更高版本。使用 JDK 21、Gradle 9.7.1、Android SDK 37.1 和 Build Tools 36.0.0。

仓库包含 Gradle Wrapper 9.7.1，可以直接用支持 AGP 9.3 的 Android Studio 打开 `android/`，等待依赖同步后构建 APK。也包含可选的 GitHub Actions 编译流程。

命令行：

```bash
cd android
./gradlew assembleDebug
```

输出路径：`android/app/build/outputs/apk/debug/app-debug.apk`。调试签名仅用于首版测试；后续更新 APK 应维持同一签名，不同 CI 运行的调试签名可能不同。

## 两台手机设置

1. 两台手机都安装 APK。
2. 填写同一个服务器根地址。
3. 假设 A 的自己的 ID 是 `alice`，对方 ID 填 `bob`；B 的自己的 ID 填 `bob`，对方 ID 填 `alice`。
4. 保存后开启“开启共享连接”。缺少通知权限时会提示并打开系统设置，授权后返回继续开启。未保存的文本不会用于连接。
5. 使用“开启应用使用情况访问权限”前往系统设置，给 PairLink 授权。
6. 需要 Shell 的手机开启本机 Shell 开关。root 由被操作手机单独请求授权；普通模式不会自动升级为 root。
7. 在另一台手机查询状态、应用或运行 `id`、`pwd` 等测试命令。
8. 暂停共享会停止服务并尝试终止本机当前 Shell。设置页修改服务器和设备 ID 前需要暂停共享。

应用不隐藏图标、不自动申请 root、不在开机时自动恢复共享。后台状态通知默认开启且静默，可在应用内直接开关，设置会保存。关闭时移除连接通知并退出前台服务，不主动断开连接；连接降为普通后台服务，更容易被 Android 和厂商省电策略停止。重新开启会恢复前台服务及静默通知，仍受系统通知权限和渠道开关限制。系统回收进程后可能重启服务，但强行停止应用后必须手动打开。按实际手机情况设置允许后台运行。本版没有持续 WakeLock。

## 开关与权限引导

每次开启通知列表、媒体播放、系统通知或状态通知开关，都会重新检查对应系统权限。系统通知同时检查应用通知权限和相应通知渠道；通知列表、媒体播放检查通知访问权限。缺少权限时开关保持关闭，自动打开对应系统设置并通过 Toast 说明需要的权限。返回后重新核验；未授予时不会启用。设备状态和应用列表没有独立授权开关，仍受 Android 自身的使用情况权限和应用可见性限制。

特权工作模式选择 Dhizuku、Shizuku / Sui 时，已有有效授权直接使用，未授权直接申请；root 会请求并验证 root 权限。只有授权成功才保存新模式，失败或服务不可用时显示错误弹窗，并保留原模式。开启应用暂停会再次验证所选模式；root、Shizuku/Sui 指令开关也分别检查实际授权，且不会自动开启远程 Shell。通知和媒体共享、应用暂停、Shell 仍保留本机确认。

## 查看对方当前通知

1. 更新双方 APK，服务端使用 `railway/` 的最新版本。
2. 被查询手机在“权限”中开启“允许对方查看通知列表”。未授予通知访问时，开关保持关闭，自动打开系统设置并 Toast 提示所需权限；授权后返回应用继续确认开启。
3. 双方开启共享，查询方点击“查看通知列表”，等待时保留弹窗和无限进度条，完成后进入卡片结果页面。
4. 关闭通知共享或撤销系统通知访问权限后，新的通知查询会被拒绝。已删除单独的通知授权按钮，由相应开关触发权限检查和引导。

读取的是系统当前可提供的通知，不保存本地通知历史，也不定时上传。普通通知、展开文本和消息通知尽量提取文字；图片、自定义布局和系统隐藏的敏感内容可能没有可读取正文。Android 15 及以上可能对验证码通知脱敏。正文每条最多 2048 字符，标题最多 256 字符，结果总量控制在现有协议上限内；超出时明确显示截断及返回条数。已经查询到的结果仍按服务器原有规则保留最多 24 小时，关闭开关不会删除既有结果。

## 查看媒体播放

双方更新 APK，服务端使用 Railway。接收方在设置页开启“允许对方查看媒体播放”，授予通知访问权限；不需要开启通知内容共享，也不需要 root、Shizuku 或 Dhizuku。查询方在“查询”页点击“查看媒体播放”，加载时显示进度弹窗，完成后进入卡片结果页。

读取 Android 系统当前活跃媒体会话，通常对应控制中心媒体面板，包含音频，也可能包含视频；无法保证每个应用的控制中心卡片都能被读取。显示应用名、包名、曲目、作者、专辑、状态、进度和时长，正在播放的会话优先。进度是查询时快照，部分播放进度根据应用提供的更新时间估算；直播或应用未提供的时长显示未知。没有会话时明确提示，不会录音、上传音频或控制播放。单次最多 20 个会话，文字有长度上限，结果沿用 24 小时清理规则。关闭媒体共享或撤销通知访问后拒绝新的查询。

## 设备状态和普通通知

状态查询会返回品牌与型号拼接值，例如 `ZYB ZPD1321`，并显示安卓版本、开机时长和最近记录的前台应用。设备状态同时显示“是否息屏”，普通息屏和非交互的息屏显示（AOD）均计为息屏。息屏时跳过前台应用查询，不返回上次亮屏时的应用；无法确定屏幕状态时也跳过查询并显示未知。查询过程中若检测到息屏，会丢弃已获取的前台应用结果。亮屏时的前台应用和应用使用列表需要使用情况访问权限；没有授权时会显示未知或提示授权。此状态是查询时的快照，不是持续监控。

发送普通通知需要发送方填写标题和内容，被操作手机开启发送授权并授予系统通知权限。通知使用普通重要性，不提供静默或紧急类型。系统关闭通知或权限不足时，请求会失败。

## Shizuku、Sui 与 Dhizuku

Shizuku/Sui 集成采用官方 API 13.1.5 的 Provider、权限申请和 UserService。安装并启动 Shizuku，或安装并启用 Sui 后，在“权限”的“特权工作模式”菜单选择 Shizuku / Sui 并授权，可用于应用暂停。远程指令另须开启“允许对方执行 Shell 指令”和“允许使用 Shell 权限执行指令”。状态显示实际 UID：ADB 启动通常为 2000，root/Sui 为 0。Shizuku 服务未启动或授权撤销时会拒绝执行，不会自动改用 root。发送方可选择本次使用 Shizuku/Sui，与 root 请求互斥。

Dhizuku 集成采用官方 API 2.6.0，用于应用暂停和恢复，不用于任意 Shell。请先按 Dhizuku 官方说明激活并启动 Dhizuku，再在“权限”的“特权工作模式”菜单选择 Dhizuku 并授权。Dhizuku 未运行、授权撤销或切换为其他工作模式时拒绝使用该方式远程操作，不会自动切换其他执行方式。

PairLink 自身的设备所有者模式、管理员接收器和激活入口已移除。旧版设备所有者执行方式默认切换为“无”，不会自动授予新的特权。若旧版 PairLink 曾被设为设备所有者，请在更新前使用旧版恢复所有暂停应用，并解除旧版设备所有者后再激活 Dhizuku。旧暂停记录保留并显示迁移提示，不能冒充新的 Dhizuku 暂停来源。

## 本机应用暂停黑名单

在设置页的“权限”中点击“管理暂停黑名单”。加载本机用户应用后，使用名称或包名搜索并勾选应用，点击“保存黑名单”生效；取消勾选后保存即可移除。退出而不保存不会更改现有黑名单。PairLink 本身和系统应用已有固定保护，无需加入黑名单。

黑名单保存在被操作手机，重启后保留。已卸载应用的黑名单记录仍显示，可手动移除，以防重新安装后失去保护。接收端在授权检查和执行前拦截黑名单应用的远程暂停请求，适用于 Dhizuku、Shizuku/Sui 和 root 三种应用暂停方式；对方不能通过远程请求修改此清单。恢复应用不受黑名单限制，加入黑名单也不会自动恢复已经暂停的应用。

黑名单针对应用暂停功能，不解析或拦截自定义 Shell 命令；任意 Shell 的实际能力仍由独立授权和执行权限决定。

## 暂停与恢复应用

设置页按“客户端偏好 → 连接设置 → 权限”排列。共享连接开启后，应用列表和设备状态默认可查询，无独立查询开关。通知列表、媒体播放、系统通知、应用暂停和 Shell 指令仍由各自授权开关控制。

1. 被操作手机在“权限”的“特权工作模式”菜单选择 Dhizuku、Shizuku / Sui 或 root。Dhizuku 和 Shizuku/Sui 须运行并授权，root 选择时单独请求本机授权；选择工作模式不会自动允许远程 Shell。新安装默认选择“无”，已有有效工作模式保留。“无”禁止远程应用暂停和恢复，但本机紧急恢复仍可使用暂停记录中的原方式。
2. 被操作手机主动开启“允许对方暂停应用”，双方共享在线。
3. 发送方在操作页点击“选择对方应用”，获取对方的用户应用列表。加载时保留无限进度条；加载完成后进入应用选择页面，用 Miuix 卡片显示应用名、包名和复选框。搜索支持应用名和包名，隐藏的搜索结果不会清除已勾选项；支持多选、刷新列表和清空选择。系统应用（包括更新后的系统应用）不列出，PairLink 本身禁用选择。点击“暂停所选”或“恢复所选”，确认清单后逐个执行。每个应用的实际结果分别以卡片显示，返回可继续选择。 首次打开时预勾选对方已由 PairLink 记录且系统仍处于暂停状态的应用；应用卡片显示暂停标记。刷新保留手动选择，并补勾新出现的暂停应用。接收方优先返回这些暂停应用以减少列表截断的影响。双方需要更新客户端才能返回和读取暂停标记；Railway 不需要更新。
4. 多选操作沿用现有单应用指令，按顺序逐个提交，不并发占用对方执行通道。单项明确失败时会记录结果并继续；离线、超时、连接错误或状态未确认时停止后续操作，标明未执行项，不自动重试。选择清单绑定获取时的服务器和双方 ID，修改连接设置后必须重新获取清单。
5. 暂停使用 Dhizuku 代理的 `setPackagesSuspended` 或当前用户的 `pm suspend`，恢复使用对应接口或 `pm unsuspend`。返回实际暂停状态；系统拒绝、命令失败和未确认状态都会明确提示。
6. 本机保存已确认暂停的包名、执行方式和 Shizuku 身份，以便执行结果回传丢失时仍可恢复；无法确认的执行状态不会记录为成功。恢复优先使用记录中的原执行方式；执行身份改变时应先恢复原身份，避免跨暂停来源误报成功。
7. “恢复已暂停的应用”不依赖服务器在线或共享开关，可恢复本机记录的暂停应用。此操作仍需要原来的系统权限或特权服务可用。恢复后若仍有其他暂停来源，结果会提示仍处于暂停状态。
8. 关闭暂停授权、关闭共享或切换方式不会自动撤销已发生的暂停。接收端对所有执行方式禁止暂停 PairLink 本身、预装系统应用及更新后的系统应用；此限制不妨碍恢复操作。其他系统保护应用也可能被安卓拒绝。

官方参考：[Shizuku API](https://github.com/RikkaApps/Shizuku-API)、[Dhizuku API](https://github.com/iamr0s/Dhizuku-API)、[应用暂停接口](https://developer.android.com/reference/android/app/admin/DevicePolicyManager#setPackagesSuspended(android.content.ComponentName,%20java.lang.String[],%20boolean))。

## 连接与权限边界

所有指令通过服务器路由，APK 本地检查共享开关和设置的对方 ID。**ID 校验仅用于路由与防止误配，不是身份验证。知道地址和 ID 的人可能冒充发送方、占用设备连接、读取结果或提交命令。开启 root Shell 后这些请求可能以 root 执行。** 这是当前无验证版本的实际行为。

最近使用记录来自安卓使用情况接口，不等于多任务卡片列表。已声明应用查询可见性来读取已安装应用的名称；无法取得应用名或系统只返回包名时，应用名显示“棍母”，包名另行保留。

普通 Shell 使用 `sh -c`，root 使用 `su -c`，在 APK 自身环境运行；Shizuku/Sui 在 UserService 的 ADB/root 身份进程中使用 `sh -c`，实际权限依赖启动方式。它是一次性命令，不提供交互、stdin、文件传输或终端会话。Shell 超时默认 20 秒，服务端最多等待 45 秒。两路输出各保留前 12000 字节。

超时或关闭开关只能尽力终止执行进程；命令已经造成的修改不会撤回，命令自行启动的独立后台进程也可能继续运行。请求超时、回传失败或退出界面后，不要直接重发有副作用的命令。接收方持久记录近期指令 ID，尽量避免重复执行。

客户端使用系统 DNS，连接可用性取决于所在网络能否访问服务器。暂不涉及域名配置。
